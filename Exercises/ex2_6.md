# 练习 2.6

*目标：*

- 探索一等对象的能力。
- 更好地理解 Python 的内存模型。

*新建文件：* `reader.py`

之前的练习编写了多个读取不同 CSV 文件的函数。这个问题显然应该能以某种方式通用化。本练习探索这一思路。

## (a) 一等数据

`Data/portfolio.csv` 中的数据按列组织，如下：

```python
"AA",100,32.20
"IBM",50,91.10
...
```

之前的代码将所有类型转换硬编码在程序中。例如：

```python
rows = csv.reader(f)
for row in rows:
    name   = row[0]
    shares = int(row[1])
    price  = float(row[2])
```

利用列表操作，可以更巧妙地完成同类转换。创建一个 Python 列表，包含对每列执行的转换：

```python
>>> coltypes = [str, int, float]
>>>
```

之所以能创建这个列表，是因为 Python 中的一切都是“一等的”（first-class）。因此，创建一个函数列表也完全可以。

现在，从上述文件中读取一行数据：

```python
>>> import csv
>>> f = open('Data/portfolio.csv')
>>> rows = csv.reader(f)
>>> headers = next(rows)
>>> row = next(rows)
>>> row
['AA', '100', '32.20']
>>>
```

将列类型与数据行通过 zip 配对，查看结果：

```python
>>> r = list(zip(coltypes, row))
>>> r
[(<class 'str'>, 'AA'), (<class 'int'>, '100'), (<class 'float'>,'32.20')]
>>>
```

注意，每个类型转换都与一个值配对，例如 `int` 与 `'100'`。现在试试：

```python
>>> record = [func(val) for func, val in zip(coltypes, row)]
>>> record
['AA', 100, 32.2]
>>>
```

确保理解以上代码。循环中，`func` 是 `str`、`int` 等类型转换函数之一，`val` 则是 `'AA'`、`'100'` 之类的值。`func(val)` 对值进行转换，类似于类型强制转换。

还可以进一步利用列标题构造字典。例如：

```python
>>> dict(zip(headers, record))
{'name': 'AA', 'shares': 100, 'price': 32.2}
>>>
```

如果愿意，也可以通过字典推导式一次完成所有步骤：

```python
>>> { name:func(val) for name, func, val in zip(headers, coltypes, row) }
{'name': 'AA', 'shares': 100, 'price': 32.2}
>>>
```

## (c) 再谈内存

[练习 2.1](ex2_1.md) 探索了内存占用，[练习 2.2](ex2_2.md) 则确定芝加哥有 181 条不同的公交线路。

```python
>>> routes = { row['route'] for row in rows }
>>> len(routes)
181
>>>
```

问题：乘车数据中包含多少个不同的线路字符串对象？这次构造对象 ID 集合，而不是线路名称集合：

```python
>>> routeids = { id(row['route']) for row in rows }
>>> len(routeids)
542305
>>>
```

想一想：只有 181 个不同的线路名称，但字典列表中有 542305 个不同的线路字符串。也许可以通过缓存或对象复用改善。Python 恰好提供了缓存字符串的 `sys.intern()` 函数。例如：

```python
>>> a = 'hello world'
>>> b = 'hello world'
>>> a is b
False
>>> import sys
>>> a = sys.intern(a)
>>> b = sys.intern(b)
>>> a is b
True
>>>
```

重启 Python，试试以下代码：

```python
>>> # ------------------ RESTART ---------```
>>> import tracemalloc
>>> tracemalloc.start()
>>> from sys import intern
>>> import reader
>>> rows = reader.read_csv_as_dicts('Data/ctabus.csv', [intern, str, str, int])
>>> routeids = { id(row['route']) for row in rows }
>>> len(routeids)
181
>>>
```

查看内存占用。

```python
>>> tracemalloc.get_traced_memory()
... look at result ...
>>> 
```

内存占用应该显著下降。观察一下，日期也大量重复。如果同时缓存日期字符串，会怎样？

```python

>>> tracemalloc.start()

>>> import reader

## (d) 特别挑战项目

[练习 2.5](ex2_5.md) 创建了 `RideData` 类，在内部按列存储全部公交数据，对用户却表现为字典序列。通过这些技巧节省了大量内存。

能把这种思路通用化吗？具体而言，能否编写通用函数 `read_csv_as_columns()`，支持以下用法：

```python
>>> data = read_csv_as_columns('Data/ctabus.csv', types=[str, str, str, int])
>>> data
<__main__.DataCollection object at 0x102b45048>
>>> len(data)
577563
>>> data[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}

此函数应该通用：给它任意文件和列类型列表，它就能读取数据。数据读入 `DataCollection` 类，在内部按列存储，但访问时表现为字典序列。

结合上一部分的字符串驻留技巧使用此函数。现在存储全部乘车数据需要多少内存？它是否仍能用于之前的 CTA 分析代码？

## (e) 深入思考

本练习编写了 `read_csv_as_dicts()` 和 `read_csv_as_columns()`，它们以相同方式向用户呈现数据。例如：

```python
>>> data1 = read_csv_as_dicts('Data/ctabus.csv', [str, str, str, int])
>>> len(data1)
577563
>>> data1[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> data1[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>>

>>> data2 = read_csv_as_columns('Data/ctabus.csv', [str, str, str, int])
>>> len(data2)
577563
>>> data2[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> data2[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>>
```

实际上，你编写的 CTA 分析代码可以使用其中任意一个函数，但内部机制完全不同。`read_csv_as_columns()` 使用另一种表示形式存储数据，依靠 Python 序列协议（特殊方法）以更有用的方式呈现信息。

这属于更广泛的“数据抽象”（data abstraction）概念。编写程序时，数据的呈现方式往往比内部组织方式更重要。虽然对外表现为字典序列，内部实现仍有很大灵活性。这是一个强大的思想，值得在编写自己的程序时思考。
