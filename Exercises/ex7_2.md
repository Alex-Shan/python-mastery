# 练习 7.2

*目标：*

- 装饰器链
- 定义接收参数的装饰器

*修改文件：* `logcall.py`, `validate.py`

## (a) 复制元数据

函数被装饰器包装后，名称、文档字符串等信息常常丢失。验证一下：

```python
>>> @logged
    def add(x,y):
        'Adds two things'
        return x+y

>>> add
<function wrapper at 0x4439b0>
>>> help(add)
... look at the output ...
>>>
```

修正 `logged`，使其正确复制函数元数据。按讲义所示使用 `@wraps(func)`。

完成后，确认装饰器保留了函数名和文档字符串。

```python
>>> @logged
    def add(x,y):
        'Adds two things'
        return x+y

>>> add
<function add at 0x4439b0>
>>> add.__doc__
'Adds two things'
>>>
```

同样修改之前的 `@validated`，使用 `@wraps(func)` 保留元数据。

## (b) 第一个带参数的装饰器

之前的 `@logged` 总是输出包含函数名的简单消息。假设希望用户能够指定自定义消息。

定义 `@logformat(fmt)`，接收格式字符串，并用 `fmt.format(func=func)` 将给定函数格式化为日志消息：

```python
# sample.py
...
from logcall import logformat

@logformat('{func.__code__.co_filename}:{func.__name__}')
def mul(x,y):
    return x*y
```

为此需要定义接收参数的装饰器，测试结果应如下：

```python
>>> import sample
Adding logging to add
Adding logging to sub
Adding logging to mul
>>> sample.add(2,3)
Calling add
5
>>> sample.mul(2,3)
sample.py:mul
6
>>>
```

为了进一步简化代码，展示如何用 `@logformat` 定义原来的 `@logged`。

## (c) 多个装饰器与方法

将装饰器用于类的方法时，情况可能有些棘手。尝试将 `@logged` 应用于以下类的方法。

```python
class Spam:
    @logged
    def instance_method(self):
        pass

    @logged
    @classmethod
    def class_method(cls):
        pass

    @logged
    @staticmethod
    def static_method():
        pass

    @logged
    @property
    def property_method(self):
        pass
```

它能工作吗？提示：不能。有什么方法能修复，使以下示例正常工作？

```python
>>> s = Spam()
>>> s.instance_method()
instance_method
>>> Spam.class_method()
class_method
>>> Spam.static_method()
static_method
>>> s.property_method
property_method
>>>
```

## (d) 再谈验证

上一练习编写了强制执行类型注解的 `@validated`。例如：

```python
@validated
def add(x: Integer, y:Integer) -> Integer:
    return x + y
```

编写新的 `@enforce()`，改为通过装饰器的关键字参数指定要强制检查的类型。例如：

```python
@enforce(x=Integer, y=Integer, return_=Integer)
def add(x, y):
    return x + y
```

被装饰函数的行为应完全相同。注意，用 `return_` 指定返回类型；`return` 是 Python 保留字，因此必须使用稍有不同的名称。
