## (a) 继承的方向

Python 继承有两个不同“方向”。第一个体现在单继承中：一系列类各自继承单个父类。例如：

```python
>>> class A:
        def spam(self):
            print('A.spam')

>>> class B(A):
        def spam(self):
            print('B.spam')
            super().spam()

>>> class C(B):
        def spam(self):
            print('C.spam')
            super().spam()


>>> C.__mro__
(<class '__main__.C'>, <class '__main__.B'>, <class '__main__.A'>, <class 'object'>)
>>> c = C()
>>> c.spam()
C.spam
B.spam
A.spam
>>> 
```

观察 `C.__mro__`，它按顺序记录了所有祖先。调用 `spam()` 时，会按照方法解析顺序（MRO）逐类向上遍历继承层次。

多重继承则允许以另一种方式组合不同的类。试试以下例子：

```
>>> class Base:
        def spam(self):
            print('Base.spam')

>>> class X(Base):
        def spam(self):
            print('X.spam')
            super().spam()

>>> class Y(Base):
        def spam(self):
            print('Y.spam')
            super().spam()

>>> class Z(Base):
        def spam(self):
            print('Z.spam')
            super().spam()

>>>
```

注意，以上类都继承共同父类 `Base`，但 `X`、`Y`、`Z` 彼此没有直接关系，也没有继承链将它们串起来。

不过，看看多重继承时发生了什么：

```python
>>> class M(X,Y,Z):
        pass

>>> M.__mro__
(<class '__main__.M'>, <class '__main__.X'>, <class '__main__.Y'>, <class '__main__.Z'>, <class '__main__.Base'>, <class 'object'>)
>>> m = M()
>>> m.spam()
X.spam
Y.spam
Z.spam
Base.spam
>>>
```

所有类按照子类指定的顺序叠在一起。如果子类调整顺序：

```python
>>> class N(Z,Y,X):
        pass

>>> N.__mro__
(<class '__main__.N'>, <class '__main__.Z'>, <class '__main__.Y'>, <class '__main__.X'>, <class '__main__.Base'>, <class 'object'>)
>>> n = N()
>>> n.spam()
Z.spam
Y.spam
X.spam
Base.spam
>>>
```

父类的顺序也随之改变。仔细观察两种情况下的 `super()`：它并非委托给每个类的直接父类，而是转到 MRO 中的下一个类。具体顺序还由子类控制。这相当特别。

共同父类 `Base` 用于终止 `super()` 调用链。具体而言，`Base.spam()` 不再调用其他方法；由于它是所有被组合类的父类，所以出现在 MRO 末尾。

## (b) 构建值验证器

[练习 3.4](ex3_4.md) 为 `Stock` 添加了检查属性类型和值的特性，例如股数必须是正整数。现在进一步探索这一思路。创建 `validate.py`，定义以下基类：

```python
# validate.py
class Validator:
    @classmethod
    def check(cls, value):
        return value
```

再创建一些类型检查类：

```python
class Typed(Validator):
    expected_type = object
    @classmethod
    def check(cls, value):
        if not isinstance(value, cls.expected_type):
            raise TypeError(f'Expected {cls.expected_type}')
        return super().check(value)

class Integer(Typed):
    expected_type = int

class Float(Typed):
    expected_type = float

class String(Typed):
    expected_type = str
```

用法如下。注意，`@classmethod` 使我们不必额外创建实际并不需要的实例：

```python
>>> Integer.check(10)
10
>>> Integer.check('10')
Traceback (most recent call last):
  File "<stdin>", line 1, in check
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>> String.check('10')
'10'
>>>
```

这些验证器可以用于函数。例如：

```python
>>> def add(x, y):
        Integer.check(x)
        Integer.check(y)
        return x + y

>>> add(2, 2)
4
>>> add('2', '3')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 2, in add
  File "validate.py", line 11, in check
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>>
```

再创建一些类，检查不同的取值范围：

```python
class Positive(Validator):
    @classmethod
    def check(cls, value):
        if value < 0:
            raise ValueError('Expected >= 0')
        return super().check(value)

class NonEmpty(Validator):
    @classmethod
    def check(cls, value):
        if len(value) == 0:
            raise ValueError('Must be non-empty')
        return super().check(value)
```

这些有什么用？现在像搭积木一样，通过多重继承组合各个类：

```python
class PositiveInteger(Integer, Positive):
    pass

class PositiveFloat(Float, Positive):
    pass

class NonEmptyString(String, NonEmpty):
    pass
```

本质上，这是把现有验证器组合成新的验证器。真够疯狂！现在用它们验证一些值：

```python
>>> PositiveInteger.check(10)
10
>>> PositiveInteger.check('10')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>> PositiveInteger.check(-10)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise ValueError('Expected >= 0')
ValueError: Must be >= 0


>>> NonEmptyString.check('hello')
'hello'
>>> NonEmptyString.check('')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise ValueError('Must be non-empty')
ValueError: Must be non-empty
>>>
```

你可能已经头晕脑胀，但把不同代码片段组合起来确实是实际程序中常见的问题。协作式多重继承是组织这类代码的一种工具。

    ...
