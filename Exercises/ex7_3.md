## (a) 再谈描述符

[练习 4.3](ex4_3.md) 定义了描述符，使用户能够定义带类型检查属性的类：

```python
from validate import String, PositiveInteger, PositiveFloat

class Stock:
    name   = String()
    shares = PositiveInteger()
    price  = PositiveFloat()
    ...
```

修改 `Stock`，加入上述描述符，变为以下形式（参见[练习 6.4](ex6_4.md)）：

```python
# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    _fields = ('name', 'shares', 'price')
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

Stock.create_init()
```

运行 `teststock.py`。加入类型检查后，应该有相当多的测试通过。很好。

## (b) 用类装饰器补齐细节

以上代码仍有 `_fields` 和最后的 `Stock.create_init()` 等多余细节，其中许多可以封装进类装饰器。

在 `structure.py` 中创建类装饰器 `@validate_attributes`，检查类体中的验证器实例并填充 `_fields`。例如：

```python
# structure.py

from validate import Validator

def validate_attributes(cls):
    validators = []
    for name, val in vars(cls).items():
        if isinstance(val, Validator):
            validators.append(val)
    cls._fields = [val.name for val in validators]
    return cls
```

这依赖于从 Python 3.6 开始类字典有序这一事实，因此会按定义顺序遇到各个 `Validator` 描述符，并据此填充 `_fields`。这样就可以编写：

```python
# stock.py

from structure import Structure, validate_attributes
from validate import String, PositiveInteger, PositiveFloat

@validate_attributes
class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

Stock.create_init()
```

运行正常后，修改 `@validate_attributes`，再执行最后的 `Stock.create_init()` 调用，使类简化为：

```python
# stock.py

from structure import Structure, validate_attributes
from validate import String, PositiveInteger, PositiveFloat

@validate_attributes
class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares
```

## (c) 通过继承应用装饰器

必须显式指定类装饰器也有点烦。为 `Structure` 添加以下 `__init_subclass__()`：

```python
# structure.py

class Structure:
    ...
    @classmethod
    def __init_subclass__(cls):
        validate_attributes(cls)
```

修改后即可完全省略装饰器，只依赖继承。这是继承加上一些隐藏机制！

```python
# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares
```

代码开始有模有样了，甚至看起来相当正常。继续推进。

## (d) 数据行转换

`Structure` 还缺少 `from_row()`，无法配合之前的 CSV 读取代码。为它添加 `_types` 类变量和以下类方法：

```python
# structure.py

class Structure:
    _types = ()
    ...
    @classmethod
    def from_row(cls, row):
        rowdata = [ func(val) for func, val in zip(cls._types, row) ]
        return cls(*rowdata)
    ...
```

修改 `@validate_attributes`，检查各验证器的 `expected_type`，据此填充上述 `_types`。

完成后，应能执行以下操作：

```python
>>> s = Stock.from_row(['GOOG', '100', '490.1'])
>>> s
Stock('GOOG', 100, 490.1)
>>> import reader
>>> port = reader.read_csv_as_instances('Data/portfolio.csv', Stock)
>>>
```

## (e) 方法参数检查

还记得之前的 `@validated` 吗？修改 `@validate_attributes`，使类中任何带注解的方法自动由 `@validated` 包装。这样就能对 `sell()` 等方法添加强制执行的注解：

```python
# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares: PositiveInteger):
        self.shares -= nshares
```

现在 `sell()` 会强制检查参数。

```python
>>> s = Stock('GOOG', 100, 490.1)
>>> s.sell(25)
>>> s.sell(-25)
Traceback (most recent call last):
  ...
TypeError: Bad Arguments
  nshares: must be >= 0
>>>
```

事情越来越有意思。类装饰器与继承的结合非常强大。
